# متابعة الوايرليس

نظام داخلي لمتابعة المشتركين الخارجين عن الخدمة لشركة تكنولوجي للإنترنت. الموظف يسجل الدخول، يرفع Excel إلى قاعدة الفريق، ثم يتعامل مع مشترك واحد كل مرة حسب الأولوية. بعد تسجيل نتيجة المكالمة ينتقل إلى المشترك التالي.

## شنو يسوي البرنامج؟

- يستورد قوائم `.xlsx` و`.xls` و`.csv`، ويتيح اختيار ورقة البيانات وربط الأعمدة.
- يحدد أولوية الاتصال: شكوى أو عطل، منطقة ضمن التغطية، عنوان يحتاج تحقق، أو بيانات هاتف ناقصة.
- يحجز استمارة مشترك لموظف واحد حتى ما يشتغل موظفان على نفس المشترك بنفس الوقت.
- يعرض بيانات المشترك والباقة وسبب الانقطاع والأسئلة المقترحة ونص المكالمة.
- بعد المكالمة، الموظف يسجل النتيجة والملاحظات ورقم التكت وموعد المتابعة عند الحاجة، ثم يضغط «حفظ والتالي».
- يحفظ العملاء ومحاولات الاتصال والإعدادات في قاعدة مشتركة بين الموظفين والأجهزة.
- يسمح بتعديل اسم الموظف واسم الشركة والعرض وساعات العمل ورقم الكول سنتر وقالب المكالمة. إعدادات القالب مشتركة، واسم الموظف خاص بحسابه.

## المتطلبات

- مستودع GitHub لنشر ملفات الواجهة عبر GitHub Pages.
- مشروع Supabase ليكون قاعدة البيانات وتسجيل دخول الموظفين.
- اتصال إنترنت لتحميل مكتبة Supabase وSheetJS من CDN.

## تجهيز قاعدة Supabase

1. أنشئوا مشروع Supabase تابعاً للشركة.
2. افتحوا **SQL Editor** وشغلوا محتوى `database.sql` مرة واحدة.
3. أنشئوا حساباً لكل موظف من لوحة Supabase Authentication. لا تفعّلوا التسجيل العام المفتوح؛ التطبيق ما بيه إنشاء حساب ذاتي.
4. من إعدادات المشروع انسخوا رابط المشروع ومفتاح **Publishable** (أو `anon` القديم). لا تستخدموا `service_role` ولا تضعوه بالواجهة.
5. عند أول فتح للموقع على كل جهاز، أدخلوا رابط المشروع ومفتاح النشر. يحفظهما المتصفح على نفس الجهاز.
6. يسجل كل موظف دخوله ببريده وكلمة مروره، ويدخل اسمه من إعدادات البرنامج.

### قاعدة البيانات والصلاحيات

الجداول مفعّل عليها Row Level Security. المستخدم غير المسجل ما يقرأ ولا يغير بيانات المشتركين. الموظفون المسجلون يشاركون قائمة العملاء وسجل المكالمات والإعدادات، وكل موظف يعدل اسمه الشخصي فقط. دالة `claim_next_customer` تحجز مشتركاً واحداً لكل موظف وتحرر الحجز القديم بعد 30 دقيقة إذا انغلق المتصفح فجأة.

راجعوا سياسات RLS قبل رفع ملف حقيقي. المفتاح الموجود في المتصفح لازم يكون Publishable/anon فقط؛ مفتاح الخدمة يتجاوز سياسات الحماية ولا يجوز نشره في GitHub أو الواجهة.

## النشر على GitHub Pages

1. ارفعوا **محتويات هذا المجلد** إلى جذر مستودع جديد، مع الاحتفاظ بالمجلد المخفي `.github/workflows`.
2. من المستودع افتحوا **Settings → Pages** واختاروا **Deploy from a branch**، ثم فرع `main` ومجلد `/ (root)`.
3. كل تحديث ترفعوه إلى فرع `main` ينشر الموقع تلقائياً. رابط الموقع يظهر بإعدادات **Pages** بعد اكتمال النشر.

## استيراد قائمة المشتركين

1. سجّل الدخول.
2. اضغط «رفع Excel للمشتركين».
3. اربط أعمدة الاسم والهاتف على الأقل، ثم المنطقة والعنوان والباقة وسعر التجديد وسبب الانقطاع ورقم التكت إذا موجودة.
4. اضغط «استيراد إلى قاعدة الفريق». هذه الخطوة ترسل الأعمدة التي ربطتها إلى مشروع Supabase الذي أدخلت رابطه حتى تصبح قاعدة مشتركة للفريق. الأعمدة الأخرى غير المربوطة لا تُخزن.
5. يبدأ الموظف بأعلى أولوية ظاهرة. بعد كل مكالمة يختار نتيجة الاتصال ويسجل التكت أو الملاحظات ثم يضغط «حفظ والتالي».

كل صف يحصل على مفتاح استيراد من رقم المشترك إن توفر، وإلا من بصمة بياناته الأساسية. إعادة رفع نفس الصف تتجاهله قاعدة البيانات بدل إنشاء تكرار. إذا تغيرت البيانات الجوهرية للصف قد يعتبره النظام صفاً جديداً.

## العرض وسعر التجديد

العرض الافتراضي لأول شهر هو 15,000 دينار. بعد ذلك التجديد يكون بسعر باقة العميل. إذا الملف ما يحتوي سعر التجديد، يظهر للموظف تذكير بفحصه من برنامج الاشتراكات. مناطق التغطية الظاهرة هي شمال العلم وجنوب العلم وشرق العلم، لكن يجب التحقق من العنوان التفصيلي في نظام الشركة قبل تأكيد توفر الخدمة.

## ملفات المستودع

- `index.html` و`styles.css` و`app.js`: الواجهة وسير العمل.
- `database.sql`: إنشاء الجداول والسياسات ودالة ترتيب/حجز الدور.
- `.github/workflows/pages.yml`: النشر التلقائي إلى GitHub Pages.

لا ترفعوا ملف بيانات المشتركين الحقيقي إلى GitHub. ارفعوا ملفات البرنامج فقط، واستوردوا قائمة العملاء بعد التأكد من إعداد مشروع Supabase وسياساته.
